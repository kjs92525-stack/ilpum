# 리버스엔지니어링 (분석·따라 만들기)

일품집 통합관리 작업용 "뜯어보기" 스킬. 두 가지 일을 돕는다.
이 저장소는 **공개(public)** 이므로, 분석 결과에 비밀번호·토큰·service_role 키·손님 개인정보를 적지 말 것.

## A. 바깥 사이트/화면을 분석해 따라 만들기

사장님이 "이 사이트처럼", "이 화면 어떻게 만든 거야" 라고 할 때.

1. **대상 확인**: 사장님이 운영/소유하는 사이트거나, 공개된 참고용 디자인인지 먼저 확인한다. 로그인 뒤 남의 데이터·유료 콘텐츠는 대상 아님.
2. **입력 받기**: 주소(URL), 스크린샷, 또는 붙여넣은 HTML/CSS 중 받을 수 있는 것을 받는다.
   - 이 샌드박스는 외부 접속이 막혀 있을 수 있다. 접속이 안 되면 사장님께 **스크린샷이나 HTML 저장 파일**을 달라고 한다(추측으로 지어내지 말 것).
3. **뜯어보기 체크리스트** — 아래를 표로 정리한다:
   - 화면 구성: 큰 영역(머리줄/왼쪽 메뉴/본문/카드) 몇 개, 어떻게 배치됐나
   - 색: 바탕·강조·글자·경고색 (가능하면 #16진수)
   - 글꼴·크기: 제목/본문/숫자
   - 모서리·여백·그림자 같은 분위기
   - 동작: 탭 전환, 접기/펴기, 실시간 갱신 등 눈에 보이는 상호작용
4. **우리 앱에 맞추기**: §2(§=CLAUDE.md)의 "정한 결정"과 충돌하는지 본다.
   - 예약 화면 디자인은 **가시성 때문에 원래 것 유지**(CLAUDE.md ㊽·㊿·51·52 — 다시 꺼내지 말 것).
   - 색은 통합 틀 기준 짙은 초록 `#1F4D3A`·금색 `#D8B16E`.
   - 새 디자인은 바로 운영에 넣지 말고 **테스트 사이트에만** 올려 사장님 확인을 받는다.
5. 바꾸면 `sh build_all.sh` 로 dist 를 다시 만들고, 관련 테스트(`sh tests/run.sh`)를 돌린다.

## B. 우리 코드 구조 분석·문서화

"우리 코드 정리해줘", "이 기능 어디 있어" 라고 할 때.

1. 먼저 `CLAUDE.md` 를 다시 읽는다 — 시스템 지도(§1)·데이터 모델(§3)·함정(§9)이 이미 정리돼 있다.
2. 찾을 때는 Grep/Glob 으로 `src/` 를 먼저 본다(`dist/` 는 빌드 결과라 고치면 다음 빌드에서 사라짐 — CLAUDE.md §9 마지막).
3. 한 기능을 정리할 때 추적 순서:
   - 화면: `src/<모듈>/*.html`, `*.css`
   - 상태·화면 그리기: `app.js` (상태는 `APP`)
   - 계산 엔진: `src/schedule/core.js` 의 `resolve` (근무·급여 공통)
   - 서버: `supabase/migrations/*.sql`(표·권한), `supabase/functions/*`(엣지 함수)
4. 결과는 **표 + 짧은 흐름 설명**으로. "어느 파일을 고치면 되는지"를 분명히 적는다(CLAUDE.md 소통 원칙 ③).
5. 긴 분석 문서는 `docs/` 에 `.md` 로 저장한다(사장님이 앱에서 열어 볼 수 있는 위치).

## 하지 않는 것

- 남의 서버·로그인 뒤 데이터·유료 콘텐츠를 긁어오기
- 바이너리 디컴파일, 악성코드 분석, 침투 테스트, 보호 우회
- 분석 결과에 anon 외의 키·비밀번호·손님 전화/이름을 남기기
